# REF-004: Small cryptographic encoding reference

- Timestamp: 2026-10-25T23:59:29.004710+00:00
- Agent: Codex
- Status: started

Implement a bounded in-memory correctness reference for permutation plus binary-field
XOR masks, using the existing AES permutation and mask-value helpers. Keep it separate
from the large-scale architecture: correctness semantics carry over, but storage,
streaming, and APIs may differ. Use separate fresh per-database masking keys, including
on re-encoding; keep coordinate identifiers separate from keys.

Add tests for permutation bijectivity, mask position binding, XOR round trips,
database key separation, re-encoding with fresh keys, repeated read positions,
and genuine Lift-RS recovery. Update [encoder requirements](../docs/encoder-contract.md),
[roadmap](../ROADMAP.md), [README](../README.md), and package documentation. Existing
file-based RM behavior remains a prototype path. No benchmark or performance claim.
Read the paper's encoding blueprint (Figure 5/Definition 5.2) and the existing
permutation, mask, decoder, and reference encoder implementations before editing.
