## Implementation

[rankPolynomialProduct](../../encoding/liftrs-shared/distributed_product.go)
consumes disjoint zero-padded row shards, computes two forward transforms,
multiplies corresponding evaluations locally, then inversely transforms the result.
Its backend bundles the existing rank transpose, Taylor window, degree metadata
and vector operations; there is no copied FFT or field recurrence. Operation IDs
are disjoint across all three transforms. Inputs are consumed. The caller must
choose a domain larger than the sum of polynomial degrees; otherwise evaluation/
interpolation gives a product modulo the domain's vanishing polynomial.

The optional `Pointwise32`/`Pointwise64` methods on
[VectorPreparation](../../encoding/liftrs-cuda/vector_preparation.go) reuse the
existing CUDA `pointwise` kernel and field tables. Left is replaced, right is
preserved; operands must be disjoint. A second bounded device tile is allocated
lazily and reused. FFT-only owners retain their previous device allocation.
Dedicated ownership and synchronous borrowing remain unchanged; old plugin
operations still work if the new optional pointwise symbol is absent. No client
CUDA/MPI dependency or resident production default changes.

same product scheduler with independent Horner/Lagrange FFT callbacks and
schoolbook multiplication, both32/64-bit slots, 1/2/3/8 ranks including empty and
uneven ownership. Input overlap, extent mismatch and operation overflow reject.
CPU/race checks pass locally and rerun before GPU work. The native plugin and
complete CPP/CUDA/MPI test binary also compile locally;
[readiness commands/hashes](readiness/checks.json), [native log](readiness/cuda-build.log),
[MPI build log](readiness/go-mpi-build.log). No MPI/GPU execution occurred locally.

The [MPI/GPU driver](../../encoding/liftrs-shared/distributed_product_gpu_test.go)
uses s4 dimensions4/5/8 and s17 dimensions5/9/12 on two ranks. Each dimension
has two synthetic base-field operand geometries: counts N/4+1 and3N/4 fill the
N-point product exactly; counts N/4 andN/2 leave a zero tail. Constants and leading
coefficients are1. These are synthetic polynomials, not genuine Lift-RS support
or a P/G identity. Both operands are generated by coordinate; no global matrix,
operand or oracle is gathered. Each rank independently computes all its expected
coefficients by schoolbook base-field multiplication. Every result is checked,
including base-field range and all padding zeros.

Direct small pointwise tests use full extension-field values (including high
components) and independent Go field multiplication, preserve right and reject
aliasing without mutation. This matters when a short evaluation subspace lies
inside the base field. The device allocation must remain stable when the second
product geometry reuses the owner. Every Taylor source snapshot and pointwise
right tile is fingerprinted against accidental mutation.

There are24 rank/product measurement rows per execution,12 direct pointwise
checks, and three complete FFTs per product. Normal and every small case under
CUDA memcheck/leak checks repeat; a separable FFT regression runs first. Largest
N is4096, longest vector64, capacity192 internal slots. Output coefficients are
saved in canonical32-bit base-field slots even when internal FFT slots are64-bit.
Output/reference files, all source/transpose proof events and phase logs persist.
The [reviewer](analyze.py) checks every byte and checksum, exact three-transform
operation/source coverage using shared FFT route reviewers, base range, constant/
leading coefficients, zero tails, rank completion and both clean CUDA summaries.
[Reviewer tests](test_review.py) reject corruption/missing windows and verify
selection of the actual product test rather than the FFT-only baseline.

## Explicit memory and time boundaries

Pointwise work adds at most one `capacity * slot_bytes` GPU tile per owner; the
largest test bound is1536 bytes extra on top of the previously used primary tile
and metadata. CUDA context/driver allocations are separate from owned bytes.
Taylor/vector kernels and host snapshots remain bounded. The product helper
retains spectra across transforms: conservatively allow caller-retained input
shards, two spectra and two transpose work shards (up to six principal host
shards), plus runtime, snapshots and32-bit diagnostic output/reference arrays.

At a hypothetical2^36-point uint64 domain /16 ranks, six host shards project
192 GiB/rank,3072 GiB aggregate before overhead. That is a control-layout upper
model, not a measured peak, selected full-size layout or resource admission.
Transfers and Taylor snapshots repeat three times; right operand H2D and left
D2H add to pointwise work. No cost is assumed zero, and no slower host-backed
mode becomes a default. Production must keep GPU arenas resident and exchange
bounded host tiles, with complete setup/communication/verification/persistence
costs measured. Fulls18 field admission, realistic large products, root/Newton/
generator integration, discovery and coordinated persistence remain later gates.
